# Milestone: First Successful iOS Simulator Build & Launch

**Date:** 2026-03-09
**Version:** v0.13.2
**Recorded by:** Historian (Explorer team)

---

## What Happened

SGraph Desktop successfully compiled, installed, and launched on an iOS Simulator for the first time. This completes the trifecta: macOS, Android, and iOS — all from the same Tauri v2 codebase.

**Device:** iPhone 16e Simulator, iOS 26.3
**Installation method:** `xcrun simctl install booted SGraph-Desktop-iOS-app`
**Build system:** GitHub Actions CI (`ci-pipeline__ios.yml`) — run #11 passed (green)

## Evidence — What Loaded

| Site | Result |
|------|--------|
| `send.sgraph.ai` | **Loaded successfully** — Beta Access screen rendered with token input, Early Access Programme sign-up form, and Test Files section all visible |

The screenshot confirms the full SGraph Send UI renders correctly in WebKit on iOS, including:
- SG/Send branding and header
- Language selector (EN-GB)
- Beta Access card with token input and "Go" button
- Early Access Programme card with Name/Email inputs and "Sign Up" button
- Test Files section at the bottom

## What This Proves

1. **Tauri v2 iOS target works** — Rust backend compiles for iOS simulator (x86_64/arm64)
2. **Remote webviews load on iOS** — WebKit-based WKWebView successfully renders `send.sgraph.ai`
3. **send.sgraph.ai loads on iOS** — unlike the initial Android experience where Send was blocked by response headers, iOS WebKit loads Send without issue (the CloudFront header fix applied for Android also benefits iOS)
4. **CI pipeline delivers** — `ci-pipeline__ios.yml` run #11 produced a working iOS app bundle after 10 prior iterations of CI fixes
5. **Simulator workflow is straightforward** — boot simulator, install app, done

## Journey to Get Here

The iOS build was described as "a bit more painful" than Android. The CI pipeline shows the effort:
- 9 failed runs before the first green build (run #11)
- Key fixes included: Xcode build script adjustments (`--silent` to `--quiet`), code signing settings moved into pbxproj patch, Tauri CLI caching improvements
- Compared to Android which had fewer CI iterations before success

## Significance

- **Three platforms from one codebase** — macOS, Android, and iOS all running within 2 days of the first mobile attempt
- **Complete Apple ecosystem** — macOS desktop + iOS mobile, both using WebKit
- **send.sgraph.ai works on iOS** — no header blocking issues (unlike initial Android)
- **Validates Tauri v2 mobile story** — the framework delivers on its promise of iOS support from a single Rust + JS codebase
