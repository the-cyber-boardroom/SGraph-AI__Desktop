# Milestone: First Successful Android Build & Launch

**Date:** 2026-03-09
**Version:** v0.13.2
**Recorded by:** Historian (Explorer team)

---

## What Happened

SGraph Desktop successfully compiled, deployed, and launched on an Android emulator for the first time. This marks the project's transition from macOS-only to multi-platform.

**Device:** Android Emulator — Medium Phone, API 36.1
**Build system:** GitHub Actions CI (`ci-pipeline__android.yml`)

## Evidence — What Loaded

| Tab | Site | Result |
|-----|------|--------|
| Vault | `vault.sgraph.ai` | Loaded successfully — full UI rendered, Access Key + Vault Key inputs visible, "Open Vault" and "Create New Vault" buttons functional |
| Tools | `tools.sgraph.ai` | Loaded successfully — hero section, "100% Client-Side" badge, tool cards (SSH Key Generator, Video, LLM Client, File Encrypt) all visible |
| Send | `send.sgraph.ai` | **BLOCKED** — `net::ERR_BLOCKED_BY_RESPONSE` — server-side `X-Frame-Options` or `Content-Security-Policy: frame-ancestors` headers prevent loading in WebView |
| Workspace | `workspace.sgraph.ai` | Not captured in screenshots |

## What This Proves

1. **Tauri v2 mobile target works** — Rust backend compiles for Android targets
2. **Remote webviews load on Android** — Chromium-based system WebView successfully renders `*.sgraph.ai` sites
3. **Bottom tab navigation works** — Send / Vault / Workspace / Tools tabs render and switch correctly
4. **Mobile app shell renders** — header bar with site branding ("SG/Vault", "SG/Tools") displays properly
5. **CI pipeline delivers** — the `ci-pipeline__android.yml` workflow produces a working APK

## Blocker Identified

`send.sgraph.ai` returns `ERR_BLOCKED_BY_RESPONSE`. This is a **server-side issue** — the site's HTTP response headers (likely `X-Frame-Options` or CSP `frame-ancestors`) block embedding in WebViews. The fix must be applied on `send.sgraph.ai`'s server configuration, not in the Desktop app. Vault and Tools do not have this restriction.

## Significance

- **Day 1 to Android in ~2 days** — from zero mobile support to a running Android app
- **Validates the architecture** — the Architect's v0.13.2 plan (single-webview navigation on mobile, platform-specific shells, shared core) is confirmed as viable
- **First multi-platform milestone** — SGraph Desktop is no longer macOS-only
