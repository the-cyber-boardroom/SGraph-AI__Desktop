## Proposed: Mobile Build Workflows

### iOS Build Workflow

```yaml
# .github/workflows/ci-pipeline__ios.yml
name: CI Pipeline - iOS

on:
  workflow_dispatch:
  push:
    branches: [main]
    paths:
      - 'src/ios/**'
      - 'src/core/**'
      - 'src-tauri/**'

jobs:
  build-ios:
    runs-on: macos-14          # Already has Xcode 15+
    steps:
      - Build with: cargo tauri ios build
      - Output: .ipa file
      - Sign with iOS distribution certificate
      - Upload to TestFlight via xcrun altool
```

**Runner:** `macos-14` — same as desktop builds. Xcode is pre-installed. No additional runner cost.

**Signing:** Uses existing Apple Developer account. Needs new secrets:
- `IOS_CERTIFICATE` + `IOS_CERTIFICATE_PASSWORD` (distribution cert)
- `IOS_PROVISIONING_PROFILE` (App Store distribution profile)

### Android Build Workflow

```yaml
# .github/workflows/ci-pipeline__android.yml
name: CI Pipeline - Android

on:
  workflow_dispatch:
  push:
    branches: [main]
    paths:
      - 'src/android/**'
      - 'src/core/**'
      - 'src-tauri/**'

jobs:
  build-android:
    runs-on: ubuntu-latest     # Android builds work on Linux
    steps:
      - Install JDK 17, Android SDK, NDK
      - Build with: cargo tauri android build
      - Output: .apk + .aab files
      - Sign with Android keystore
      - Upload to Google Play via fastlane
```

**Runner:** `ubuntu-latest` — cheaper than macOS runners. Android SDK/NDK need installing.

**Build targets:** 3 architectures:
- `aarch64-linux-android` (most modern phones)
- `armv7-linux-androideabi` (older phones)
- `x86_64-linux-android` (emulators, some Chromebooks)

**Signing:** Needs Google Play Developer account + keystore. New secrets:
- `ANDROID_KEYSTORE` (base64)
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

## Distribution Channels

### iOS

| Channel | Review required | Audience | Setup effort |
|---------|----------------|----------|-------------|
| **TestFlight** | No (for < 10k testers) | Internal team, beta testers | Low — upload via `xcrun altool` |
| **App Store** | Yes (Apple review) | Public | Medium — screenshots, metadata, privacy policy |
| **Enterprise** | No | Organisation only | Requires Enterprise account ($299/year) — not recommended |

**Recommendation:** Start with TestFlight, graduate to App Store after adding native features.

### Android

| Channel | Review required | Audience | Setup effort |
|---------|----------------|----------|-------------|
| **APK (GitHub Release)** | No | Anyone (sideload) | Zero — just upload to release |
| **Internal testing** | No | Up to 100 testers | Low — Google Play Console |
| **Open testing** | Automated checks | Public beta | Medium — basic app listing |
| **Production** | Yes (Google review) | Public | Medium — full listing + data safety |

**Recommendation:** Start with APK on GitHub Releases (instant), then Google Play internal testing, then production.

## Signing Setup Checklist

### iOS (Reusing Apple Developer Account)

- [ ] Generate iOS Distribution certificate in Apple Developer portal
- [ ] Create App ID: `ai.sgraph.desktop` (or `ai.sgraph.desktop.ios`)
- [ ] Create App Store distribution provisioning profile
- [ ] Export certificate as .p12, base64-encode, add to GitHub Secrets
- [ ] Base64-encode provisioning profile, add to GitHub Secrets
- [ ] Create app in App Store Connect

### Android (New Google Account)

- [ ] Register Google Play Developer account ($25 one-time fee)
- [ ] Generate signing keystore: `keytool -genkey -v -keystore sgraph-desktop.jks -keyalg RSA -keysize 2048 -validity 10000 -alias sgraph-desktop`
- [ ] Base64-encode keystore, add to GitHub Secrets
- [ ] Add keystore password, key alias, key password to GitHub Secrets
- [ ] Create app in Google Play Console
- [ ] Set up Google Play App Signing (recommended — Google manages the release key)

|----------|-----------|-------------|
| macOS Desktop (per arch) | ~2-4 min | macOS runner (10x Linux cost) |
| iOS | ~3-5 min | macOS runner (10x Linux cost) |

**Total CI time for full release (all platforms):** ~15-20 minutes (running in parallel).

## Recommendation

1. **Phase 6 of the dev plan** — implement mobile CI workflows after the shells are functional
2. **iOS signing first** — reuses existing Apple account, lowest friction
3. **Android signing second** — needs new Google account, but APK distribution is simpler (no review)
4. **Path-scoped triggers** — mobile CI only runs when mobile-relevant files change
5. **Separate workflows per platform** — keeps build logic clean, allows independent releases
